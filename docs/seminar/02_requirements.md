# Задание 2. Требования и уточнение задачи

## Проект

**NoteVision OMR — анализ сканированных нотных документов РГБ**

## 1. Назначение системы

NoteVision OMR предназначена для локальной пакетной обработки сканированных
нотных документов и связанных библиографических метаданных.

Система выполняет следующие операции:

- организует PDF и MRC/MARC-файлы по идентификатору документа;
- извлекает страницы PDF в изображения PNG;
- выделяет страницы с нотной записью;
- поддерживает ручную валидацию автоматической классификации;
- формирует список OMR-кандидатов;
- повторно извлекает OMR-страницы при 300 DPI;
- запускает Audiveris и получает MusicXML/MXL;
- преобразует MXL в MIDI;
- сохраняет CSV/JSON-отчёты о каждом этапе.

Система ориентирована на исследовательский MVP и запускается через CLI.
Промышленный web-сервис, облачное развёртывание и собственная модель
распознавания нотных символов в текущую версию не входят.

## 2. Пользовательские роли

| Роль | Сценарии | Ожидаемый результат |
|---|---|---|
| Исследователь / студент | Импортирует документы, запускает batch pipeline, анализирует метрики и результаты OMR | Структурированный корпус страниц, метаданные, labels, MXL/MIDI и отчёты |
| Музыкант | Открывает MXL в MuseScore, импортирует MIDI в DAW, проверяет музыкальный материал | Редактируемая партитура и MIDI для прослушивания или дальнейшей обработки |
| Оператор разметки | Проверяет автоматические метки в CSV и HTML-галерее, исправляет `has_music` и `page_type` | Валидированная разметка страниц и очищенный список OMR-кандидатов |
| Разработчик | Добавляет этапы pipeline, запускает тесты, анализирует журналы ошибок | Модульный воспроизводимый код с контролируемыми входами и выходами |
| Преподаватель / проверяющий | Проверяет постановку задачи, требования, метрики, ограничения и демонстрационный сценарий | Документированные результаты MVP без смешения технической успешности и экспертного качества |

## 5. Интерфейсы

В текущем MVP отсутствуют REST API и web-интерфейс. Взаимодействие с системой
выполняется через CLI и файловые форматы.

| Команда | Назначение | Вход | Выход |
|---|---|---|---|
| `organize_raw_files.py` | Организация загруженных файлов по `doc_id` | `data/inbox/*.pdf`, `*.mrc` | `data/raw/<doc_id>/`, `raw_import_report.csv` |
| `extract_pages.py` | Извлечение всех страниц одного PDF | PDF или каталог документа | PNG-страницы и `manifest.csv` |
| `parse_mrc.py` | Парсинг одного MRC/MARC-файла | MRC или каталог документа | JSON в консоли и опционально в файле |
| `batch_run_pipeline.py` | Обработка всех документов | `data/raw/` | Страницы, metadata JSON, predictions, batch report |
| `build_labels_template.py` | Создание шаблона ручной разметки | `all_page_predictions.csv` | CSV-шаблон labels |
| `evaluate_batch.py` | Расчёт общих и подокументных метрик | Валидированные labels и каталог predictions | JSON с метриками |
| `build_review_gallery.py` | Визуальная проверка разметки | Labels CSV | Локальная HTML-галерея |
| `preprocess_music_pages.py` | Контрастная нормализация и бинаризация нотных страниц | Валидированные labels | Бинарные PNG и preprocessing report |
| `build_omr_candidates.py` | Формирование списка страниц для OMR | Валидированные labels | `omr_candidates.csv` |
| `extract_omr_pages.py` | Повторное извлечение кандидатов при 300 DPI | Candidates CSV и исходные PDF | `outputs/omr_pages/<doc_id>/page_XXX.png` |
| `run_audiveris_omr.py` | Запуск Audiveris для одной страницы или batch | PNG, labels или candidates CSV | MXL/OMR, логи и `omr_report.csv` |
| `summarize_omr_results.py` | Сводка технических результатов OMR | OMR report и каталог OMR | `omr_summary.json` |
| `convert_mxl_to_midi.py` | Преобразование MXL в MIDI | Один MXL или каталог MXL | MIDI и `midi_conversion_report.csv` |

## 6. Форматы данных

### Входные форматы

| Формат | Назначение |
|---|---|
| PDF | Сканированный нотный документ |
| MRC/MARC | Библиографическая запись документа |
| CSV labels | Ручная или полуавтоматическая разметка страниц |
| PNG | Извлечённые и предобработанные изображения страниц |
| MXL/MusicXML | Машиночитаемая партитура после OMR |
| MIDI | Представление музыкальных событий для воспроизведения и DAW |

### Основные выходные пути

| Путь | Содержание |
|---|---|
| `outputs/pages/<doc_id>/page_XXX.png` | Страницы основного pipeline |
| `outputs/reports/*.json` | Метрики, metadata и OMR summary |
| `outputs/reports/*.csv` | Манифесты, prediction, error и batch-отчёты |
| `outputs/omr_pages/<doc_id>/page_XXX.png` | Страницы OMR-кандидатов при 300 DPI |
| `outputs/omr_300dpi/<doc_id>/page_XXX/*.mxl` | Результаты Audiveris |
| `outputs/midi/<doc_id>/page_XXX.mid` | MIDI после конвертации MXL |

Имена страниц используют индексацию с единицы и формат `page_XXX`.

## 7. Данные и права

- Исходные PDF и MRC хранятся локально в `data/raw/<doc_id>/`.
- Содержимое `data/raw` и `data/inbox` исключено из Git через `.gitignore`.
- Производные данные в `outputs/` также не включаются в репозиторий.
- В Git сохраняются код, документация, тесты и пустая структура каталогов
  через `.gitkeep`.
- В MVP не обрабатываются персональные данные.
- Использование материалов РГБ в исследовательском MVP не означает
  автоматического разрешения на массовую публикацию исходников или
  производных данных.
- Перед масштабированием необходима отдельная проверка правового режима
  конкретных коллекций, сроков охраны и условий доступа.

## 9. Границы требований

### Входит в текущую версию

- локальный CLI pipeline;
- организация PDF/MRC;
- извлечение и классификация страниц;
- baseline detector;
- ручная валидация;
- Audiveris OMR;
- повторное извлечение при 300 DPI;
- MXL→MIDI;
- CSV/JSON/HTML-отчёты;
- автоматические тесты ключевых сценариев.

### Не входит в текущую версию

- web UI;
- REST API;
- cloud deployment;
- собственная нейросетевая OMR-модель;
- полная экспертная оценка всех распознанных нот;
- поиск по мелодии и музыкальным признакам;
- промышленное масштабирование;
- юридическое оформление массовой публикации данных.

## 10. Вывод

Функциональные и основные нефункциональные требования MVP выполнены:
реализован локальный воспроизводимый pipeline от PDF/MRC до MXL и MIDI,
получены метрики детектора, проведены batch-эксперименты Audiveris и проверена
конвертация MIDI.

Для развития проекта в рамках ВКР требования необходимо расширить в сторону:

- формальной оценки качества OMR на уровне нот, длительностей, тактов и голосов;
- увеличения и стратификации корпуса;
- экспертной проверки MXL;
- поиска и анализа музыкального содержания;
- оценки производительности и масштабирования;
- уточнения правового режима производных данных.
