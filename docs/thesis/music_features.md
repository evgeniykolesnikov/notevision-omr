# Извлечение музыкально-теоретических характеристик

## Назначение

Модуль дополняет технический результат OMR структурированными признаками,
которые явно присутствуют в MXL/MusicXML. Он извлекает ключевые знаки и
тональность, размер, ключи, партии, инструменты и число тактов. Эти данные
используются в document dashboard, отчётах и последующих исследовательских
экспериментах.

Извлечение признаков не доказывает музыкальную корректность распознавания.
Если Audiveris записал ошибочную ноту, размер или ключ, extractor аккуратно
прочитает именно это значение. Для оценки качества по отношению к скану нужна
экспертная проверка или ground truth.

## Источники

Поддерживаются два режима:

1. `--omr-report` читает OMR-отчёт. Для постраничных строк используются явные
   пути MXL/MIDI. Для агрегированных строк файлы ищутся в primary и
   fallback-каталогах по `doc_id`.
2. `--input-dir` рекурсивно обходит один или несколько каталогов с `.mxl`,
   `.musicxml` и `.xml`.

Пример:

```powershell
python scripts/extract_music_features.py --omr-report outputs/reports/omr_pipeline_report.csv --out outputs/reports/music_features.csv
```

## Поля результата

- `doc_id`, `page_index` связывают признаки со страницей корпуса.
- `source_path`, `midi_path` фиксируют использованные артефакты.
- `key_fifths`, `mode` описывают ключевые знаки и явно заданный лад.
- `detected_tonality_*` содержит конкретную тональность только при наличии
  `major` или `minor`.
- `key_signature_name_*` содержит параллельные варианты, если лад отсутствует.
- `time_signatures`, `clefs`, `parts`, `part_names`, `instruments` перечисляют
  уникальные значения через `;`.
- `measures_count` содержит максимальное число тактов среди партий страницы.
- `confidence` оценивает полноту явных данных от `0.0` до `1.0`.
- `error` сохраняет диагностическое сообщение без остановки всего запуска.

## Статусы

| Статус | Значение |
|---|---|
| `success` | Найдены ключевые знаки и размер |
| `no_key` | MusicXML разобран, но ключевые знаки не найдены |
| `no_time_signature` | Ключевые знаки найдены, размер отсутствует |
| `parse_error` | Файл существует, но не разобран |
| `missing_file` | Ожидаемый MXL/MusicXML отсутствует |

## Тональность и ключевые знаки

Если MusicXML содержит mode `major` или `minor`, система формирует конкретную
тональность, например `C-dur / до мажор` или `a-moll / ля минор`.
Для си мажора используется запись `B-dur`, совпадающая с текущим отображением
pitch names в проекте; эта договорённость зафиксирована явно и не смешивается
с немецкой нотацией `H-dur`.

Если указан только key signature без mode, система показывает пару
параллельных вариантов, например `D-dur / b-moll`, но оставляет
`detected_tonality_*=unknown` и `mode_status=unknown`. Эвристический вывод по
распределению нот в текущей версии не выполняется.

## Ограничения

- Результат относится к одной OMR-странице, а не обязательно ко всему
  произведению.
- На странице могут встречаться несколько размеров, ключей и инструментов.
- Названия партий зависят от качества экспорта Audiveris.
- Успешный разбор MusicXML является техническим, а не экспертным критерием.
- Confidence не следует интерпретировать как вероятность музыкальной
  правильности.
