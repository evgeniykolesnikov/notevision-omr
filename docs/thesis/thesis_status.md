# Текущее состояние ВКР NoteVision OMR

## 1. Краткое описание проекта

NoteVision OMR предназначен для анализа сканированных нотных документов
цифровой библиотеки. Система реализует воспроизводимый локальный pipeline:

`PDF → страницы → классификация музыкальных страниц → Audiveris OMR → MusicXML/MXL → MIDI`.

На этапе проектного семинара была подтверждена техническая проходимость
pipeline на небольшом корпусе. В ветке ВКР работа расширена в четырёх
направлениях:

- корпус увеличен до 41 документа;
- выполнена дополнительная ручная валидация страниц;
- пересчитаны метрики detector на расширенной выборке;
- сформирована отдельная выборка и проведена page-level оценка OMR pipeline.

Технический успех создания MXL или MIDI не считается доказательством
музыкальной точности результата. Содержательная оценка нот, длительностей,
голосов и тактов остаётся отдельной задачей ВКР.

## 3. Ручная валидация

Для управляемой проверки корпуса используется
[приоритетная выборка](../../data/labels/pages_review_priority_thesis.csv).
Она включает спорные страницы, границы документов, страницы с низкой
уверенностью detector и контрольную выборку уверенных музыкальных страниц.

Локальная editable review gallery показывает изображение и текущие поля
разметки, поддерживает быстрые действия, фильтры, автосохранение в
`localStorage` и экспорт исправлений. Экспорт сохраняется в
[thesis_label_corrections.csv](../../data/labels/thesis_label_corrections.csv),
после чего применяется к основной разметке отдельным CLI-скриптом.

Поле `validation_source` позволяет различать происхождение метки:

- `manual_previous` — ручная проверка, перенесённая из корпуса проектного
  семинара: **429 страниц**;
- `manual_thesis` — ручная проверка в рамках ВКР: **312 страниц**;
- `template_prediction` — значение шаблона detector, ещё не подтверждённое
  вручную: **1643 страницы**.

Классы введены для отделения содержимого страницы от бинарного признака
`has_music`:

- `title` — титульные листы, обложки и издательская информация;
- `text` — оглавления, предисловия и текст без существенной нотной записи;
- `blank` — пустые страницы, номера страниц, bleed-through и ghosting;
- `music` — страницы, где нотная запись является основным содержимым;
- `mixed` — существенный текст вместе с существенной нотной записью;
- `bad_scan` — технически непригодное для OMR изображение;
- `unknown` — страницы, тип которых нельзя надёжно установить без
  дополнительной проверки.

Такая схема позволяет отдельно анализировать ошибки detector, качество
сканов и применимость страницы для OMR.

## 4. Метрики music-page detector

Метрики рассчитаны скриптом `scripts/evaluate_music_detector.py` по полям
`has_music` и `has_music_pred` из текущей валидированной разметки.

| Показатель | Значение |
|---|---:|
| TP | 2059 |
| FP | 39 |
| TN | 225 |
| FN | 61 |
| Accuracy | 0,9581 |
| Precision | 0,9814 |
| Recall | 0,9712 |
| F1 | 0,9763 |

Detector демонстрирует высокую precision, но на расширенном корпусе появились
61 false negative. Это важное отличие от результата проектного семинара:
расширение корпуса выявило страницы, недостаточно хорошо покрываемые
исходными rule-based признаками.

Постраничный анализ хранится локально в
`outputs/reports/error_analysis.csv`, а визуальная проверка выполняется через
`outputs/reports/error_gallery.html`.

## 5. OMR Evaluation

Для оценки полного pipeline сформирована
[выборка из 150 страниц](../../data/labels/omr_eval_sample_thesis.csv).
Она включает страницы `music` и `mixed`, ручные метки, страницы проблемных
документов и примеры с низкой уверенностью detector.

Текущий файловый контроль pipeline дал следующие результаты:

| Показатель | Значение |
|---|---:|
| Размер OMR-выборки | 150 страниц |
| Документы в выборке | 14 |
| Страницы с MXL | 141 |
| Страницы с MIDI | 141 |
| OMR success rate | 94,00% |
| End-to-end MIDI success rate | 94,00% |
| Страницы без MXL | 9 |
| Страницы с MXL, но без MIDI | 0 |

Все 141 страницы, для которых был сформирован MXL, также имеют итоговый MIDI.
Девять неудачных страниц остановились на стадии Audiveris/MXL. Подробные
результаты приведены в [отчёте OMR evaluation](omr_evaluation.md).

Эта оценка отражает наличие технических артефактов для страницы. Она не
измеряет корректность музыкального содержимого MXL и MIDI.

## 6. Анализ ошибок

Текущий failure report содержит девять страниц типа `missing_mxl`. Среди них
три страницы размечены как `mixed`, остальные — как `music`. Наблюдаемые и
ожидаемые сложные случаи для дальнейшего анализа:

- `mixed`-страницы с крупным текстовым блоком и небольшим нотным фрагментом;
- фото страниц и разворотов с перспективными искажениями;
- рукописная нотная запись;
- нестандартное расположение системы, поворот или плохое выравнивание;
- страницы с техническими элементами оцифровки, включая color calibration
  patches;
- низкий контраст, обрезка и неоднородный фон.

Для девяти текущих сбоев эти причины ещё не подтверждены постраничным анализом
логов. Ближайшая задача — сопоставить failure report, изображения и логи
Audiveris, после чего присвоить каждой странице конкретную категорию причины.

Color calibration patches предусмотрены правилами разметки как возможный
признак `bad_scan`, однако в текущем `pages_validated_thesis.csv` нет
окончательно подтверждённых страниц класса `bad_scan`.

## 7. Текущее состояние репозитория

- `seminar-v1.0` — зафиксированная версия MVP проектного семинара;
- `thesis` — текущая ветка разработки ВКР.

Основные каталоги:

| Каталог | Назначение |
|---|---|
| `docs/thesis/` | план, правила разметки, статистика и главы ВКР |
| `data/labels/` | inventory, валидированные labels и evaluation samples |
| `scripts/` | CLI-команды подготовки данных, оценки и отчётности |
| `tests/` | автоматические тесты модулей и CLI-логики |

Локальные исходники находятся в `data/raw`, а промежуточные результаты и
отчёты исполнения — в `outputs`. Эти каталоги не должны коммититься, за
исключением специально разрешённых служебных файлов.

## 9. Следующие шаги

### Ближайшие шаги

- повторить OMR evaluation на более сбалансированной по документам, типам
  страниц и сложности выборке;
- добавить `skip-existing` и resume-механику для пакетного запуска Audiveris;
- уточнить причины ошибок для девяти страниц без MXL по изображениям и логам;
- подготовить финальные таблицы и графики по корпусу, detector и OMR;
- проверить согласованность CSV-отчётов с текстовыми разделами ВКР после
  каждого нового эксперимента.

### Среднесрочные шаги для ВКР

- улучшить detector для фотографий, разворотов и рукописных страниц;
- сравнить Audiveris с альтернативным OMR-подходом на одной контрольной
  выборке;
- оценивать MusicXML не только по факту создания файла, но и по корректности
  музыкальной структуры;
- сформировать экспертную ground truth для ограниченного набора страниц;
- добавить symbol-level и measure-level метрики для нот, длительностей,
  тактов, голосов и повторов;
- сформулировать рекомендации по применимости pipeline для разных типов
  документов цифровой библиотеки.

## 10. Научная новизна и исследовательская ценность

Анализ исторических нотных документов сложнее стандартного OMR на современных
цифровых или специально подготовленных изображениях. Библиотечный документ
проходит через печать, хранение, фотографирование или сканирование, поэтому на
результат одновременно влияют состояние оригинала, полиграфия, геометрические
искажения, фон бумаги, обрезка, разворот и параметры оцифровки. Кроме того,
один PDF может содержать не только ноты, но и обложки, титульные листы,
предисловия, пустые страницы и технические кадры.

Корпус РГБ отличается от современных MusicXML-датасетов тем, что его исходной
формой являются реальные библиотечные PDF-сканы и MRC/MARC-метаданные, а не
заранее нормализованные изображения с готовой структурированной нотной
разметкой. Для большинства страниц отсутствует эталонный MusicXML и
symbol-level ground truth. Поэтому исследование включает не только собственно
OMR, но и подготовку корпуса, классификацию страниц, ручную валидацию,
сопоставление метаданных и анализ технических ошибок полного pipeline.

В ходе работы выявлены характерные особенности корпуса:

- `mixed`-страницы, где существенная нотная запись соседствует с крупным
  текстовым блоком;
- рукописные страницы, структура и графика которых отличаются от печатных
  нот;
- фотографии страниц и разворотов с перспективными искажениями;
- технические кадры и элементы оцифровки, включая color calibration patches;
- нестандартная вёрстка, неоднородное расположение систем и сложная структура
  страницы;
- старые сканы с низким контрастом, шумом, обрезкой, bleed-through и
  геометрическими дефектами.

Исследовательская ценность текущей работы состоит в создании воспроизводимой
основы для изучения OMR на библиотечных фондах. Зафиксированы структура
данных, правила разметки, page-level метрики, управляемая OMR-выборка,
совместимые CLI-интерфейсы и отчёты об ошибках. Это позволяет повторять
эксперименты, расширять корпус и сравнивать методы на одинаковых входных
данных. Строгое обоснование научной новизны должно быть дополнено обзором
публикаций и существующих исторических OMR-корпусов.

## 11. Потенциальные направления развития

### Краткосрочные

- улучшить music-page detector для сложных, смешанных и низкоконтрастных
  страниц;
- расширить корпус новыми документами и типами нотных изданий;
- продолжить ручную разметку, уделяя приоритетное внимание `unknown`,
  `mixed`, фотографиям, рукописям и страницам с низкой уверенностью detector.

### Среднесрочные

- сформировать symbol-level ground truth и оценивать распознавание отдельных
  нотных символов;
- добавить measure-level evaluation для структуры тактов, голосов,
  длительностей и повторов;
- оценивать качество MusicXML содержательно, а не только по наличию
  технически корректного файла.

### Долгосрочные

- реализовать поиск по музыкальному содержимому распознанных документов;
- сравнивать музыкальные произведения и их фрагменты;
- находить дубли, переиздания, редакции и варианты одного произведения;
- интегрировать музыкальные признаки и результаты OMR с библиотечными
  каталогами и библиографическими метаданными.
